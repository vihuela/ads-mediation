## Why

当前全屏广告展示入口主要消费已有缓存，缺少由业务场景管理的统一等待、超时与取消能力，页面切换和 Compose 重组也需要明确的展示有效性约束。第一阶段先分离加载请求与展示机会，让场景失效只结束本次展示资格，并保留进行中的加载和可用缓存，供下一次有效广告场景复用。

## What Changes

- 为开屏、插屏和激励广告增加可等待广告就绪的展示入口，沿用回调风格并返回可取消的展示机会句柄；保留现有立即尝试展示入口的语义。
- 每次展示机会绑定发起时的 Activity 与业务场景，并拥有独立等待期限。期限从机会创建时开始计算，不因加载回调、初始化完成或普通 Compose 重组而重置；后续明确触发的新机会拥有自己的等待期限。
- 在调用 SDK `show()` 前，等待超时、宿主取消、页面失效、应用退后台或绑定的 Activity 销毁、被替换，均使该机会结束。结束后的机会不能因迟到回调或页面返回而恢复，也不自动转移到新的 Activity；已经交给 SDK 展示的广告不承诺由等待取消操作撤回。
- 展示机会结束不取消底层加载、不清空已有缓存。下一次兼容的机会优先使用有效缓存，或继续等待同一平台、广告类型和广告位下尚未完成的加载；只有确有加载需要时才按现有加载机制发起请求，不因场景重入重复发起同一在途加载。
- 加载完成只更新缓存并通知仍有效的等待机会，没有有效机会时仅保留缓存。实际展示前再次确认期限、场景和 Activity 有效性及全屏占用，避免取消与加载完成相邻发生时误展示；每次机会只产生一次最终结果，并保留正常展示后的关闭、失败、奖励和收入处理。
- 提供 Compose 接入约定：普通重组复用同一机会，业务场景离开时明确取消，返回场景后由新的业务触发创建新机会；核心库不引入 Compose 或 Navigation 依赖。
- 第一阶段沿用现有平台和同广告类型的缓存竞价能力。跨广告类型竞价、平台扩展架构、原生广告和横幅广告留在后续阶段。

## Capabilities

### New Capabilities

- `fullscreen-display-opportunities`: 定义全屏广告展示机会的创建、等待、超时、取消、场景有效性和结果边界，以及机会之间对在途加载与有效缓存的复用行为。

### Modified Capabilities

无。项目当前尚无已登记的能力规范。

## Impact

- 公共 API：`Ads` 增加等待展示入口和机会句柄；明确等待结束原因与现有 `AdShowResult`、`AdRewardResult` 的对应关系。
- 内部流程：涉及 AdMob、TopOn 的加载状态与就绪通知、竞价选择、全屏展示占用和生命周期监听，复用现有预加载及缓存机制。
- 现有自动开屏：设计阶段明确 `autoShowAppOpen` 与手动展示机会的触发责任和协调方式，以及多个展示机会同时到来时的处理策略。
- 事件语义：设计阶段明确等待机会与加载请求、展示会话的对应关系，区分机会结束原因和 SDK 加载结果，避免迟到回调造成重复结果或重复上报。
- 验证与文档：补充超时后加载继续、下一机会复用、页面离开与重组、取消与就绪竞态的验证，并提供宿主接入说明。
